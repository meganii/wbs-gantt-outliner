# UI 総点検レポート（3面構成: WBS / 統合表示 / ガントチャート）

作成: October 17, 2026

## 0. この文書の目的

画面 UI を「一般的なタスク管理ツール」と比較し、統合的な観点で課題を洗い出して、
今回の改修でどこまで・どの順で直すかを決めるための下敷きにする。

- 方法: 実アプリをブラウザで起動（`scratch/vite.web.config.ts` + `scratch/shot.mjs`）し、
  リアルなサンプルプロジェクト（3 フェーズ / 13 タスク / 依存関係あり）を読み込んで
  3 ビューとダイアログのスクリーンショットを取得して確認した。
- 取得画像: `scratch/shots/{integrated,wbs,gantt,integrated-selected,dialog}.png`（ローカルのみ）

## 1. 現状の 3 ビュー概要

| ビュー | 構成 | 主な用途 | 気づき |
| --- | --- | --- | --- |
| WBS | 左の全カラム表のみ（横スクロール可） | 階層編集・詳細入力 | 日付セルで文字が重なる（後述 P0-1） |
| 統合表示 | 左ペイン（列）+ 右タイムライン | 既定ビュー・同時操作 | 左ペインが 600px 固定で列が消える（P0-2） |
| ガントチャート | タスク名列 + 右タイムライン | スケジュール把握 | 今日ライン無し、左列が名前のみ（P1-1/P1-2） |

3 ビューはいずれも `TaskRow` / `GanttTimelineRow` / `TimelineHeader` を共有しており、
構造としては整理されている。課題は主に「見た目の一貫性」「情報の出し方」「壊れた表示」。

## 2. 一般タスク管理ツールとの比較（ギャップ）

| 観点 | 一般ツール（Linear / Asana / Jira / Notion / OmniPlan 等） | 本アプリ | ギャップ |
| --- | --- | --- | --- |
| ヘッダー | ブランド + プロジェクト名 + ビュー切替 + 主要アクション（検索/フィルタ/追加/設定）を階層化 | テキストボタンの横並び。階層・グルーピングが無い | 中 |
| 余白/字サイズ | 12/13/14px を使い分け、見出しと本文に差 | ほぼ全て `text-xs`（12px）で平板 | 大 |
| 角丸/影/罫線 | 角丸・やわらかい罫線・アクセントカラー | 角丸ほぼ無し・`gray-300` 罫線・native な select | 大 |
| 検索/フィルタ | 常設。キーボードで即絞り込み | 無し | 大 |
| 日付表現 | 今日ライン、遅延の赤表示、マイルストーン | 今日ライン無し・遅延表現無し | 大 |
| 状態表現 | バッジ/ピル、色で状態を即認 | native な select + 数値入力 | 中 |
| 行の選択 | 行全体（タイムライン含む）をハイライト | 左ペインのみ。バーと対応が追いにくい | 中 |
| 空状態 | 誘導付きの空状態 | WBS のみ。統合/Gantt は真っ白 | 中 |
| 用語/言語 | 一貫した言語 | ダイアログだけ英語 | 小（だが目立つ） |

## 3. 課題一覧（優先度付き）

### P0: 壊れている / 使えない（早急に直す）

- **P0-1. 予定日付・実績日付セルの文字重なり（WBS ビュー）**
  - 症状: セルに `yy0/10/05 dd` のように表示値とプレースホルダ `yyyy/mm/dd` が重なって見える。
  - 原因: `TaskDateCell` / `TaskPlanDateCell` の `localStart` は `useState('')` で初期化されるが、
    「値が無い & 非フォーカス」の初回は同期分岐（`syncedStart` 比較）が走らず空のまま。
    結果 input の value が空になり、透明文字のはずの input の **placeholder が可視**になって
    背面の Overlay Span（`10/05`）と重なる。実 DOM で `value:""` / `placeholder:"yyyy/mm/dd"` を確認済み。
  - 影響: WBS ビューの日付列が常時読みにくい。ユニットテストは Overlay Span を見るため検知できていない。
  - 参照: `src/components/cells/TaskDateCell.tsx:35-70`, `TaskPlanDateCell.tsx`

- **P0-2. 統合表示の左ペインで列が消えて到達不能**
  - 症状: 既定の表示列は 10 列（合計 約 1,532px: taskName200 + description256 + assignee128 +
    deliverables192 + status100 + progress80 + planDuration64 + planDate224 + duration64 + date224）だが、
    統合表示の左ペインは `outlinerWidth` の既定 600px 固定 + `overflow-hidden`。
    ステータス/進捗/日付が画面外になり、横スクロールもできない（＝触れない）。
  - 参照: `src/hooks/useOutlinerResize.ts:27`（initialWidth=600）, `IntegratedView.tsx:62-67`

- **P0-3. トーストが右上の操作系に重なる**
  - 症状: 読み込み直後のトーストがタイムライン右上の `Day/Week/Month/Year` セレクタ・ヘッダーに被る。
  - 参照: `ToastContainer.tsx:87`（`top-12`）

### P1: 使い勝手（設計から見直す）

- **P1-1. タイムラインに「今日」ラインが無い。**スケジュール把握の基準点が無い。
  （`today` は初回スクロール位置にしか使われていない）
- **P1-2. ガント左列がタスク名のみ（既定 200px）。**WBS 番号インデントと「New Task」入力があるため
  名前がすぐ切れる。統合表示と情報量が非対称。
- **P1-3. 選択行のハイライトが左ペインで止まる。**右のバー領域が無地のため、
  選択中の行のバーがどれか追いにくい（HANDOFF ではちらつき対策で意図的に透明化した経緯あり）。
- **P1-4. 見た目の階層が平板。**全ボタン `text-xs` + `gray-100` の平坦なツールバー、
  アクセントは青 1 色。視覚的なグルーピング・優先度が読み取れない。
- **P1-5. ツールバー/ヘッダーに検索・フィルタ・「今日へ戻る/ズーム」が無い。**大規模 WBS で目的の行に辿り着けない。
- **P1-6. ヘッダーの月ラベルが横スクロールで切れる。**セグメント先頭に固定しているため、
  セグメント先頭が画面外にスクロールするとラベルも消える（`TimelineHeader.tsx:92-103`）。
- **P1-7. 行の右クリックメニューが無い。**列ヘッダのみ。追加/削除/インデント/依存の入口が少ない。
- **P1-8. ドラッグハンドルがホバー時のみ低 opacity。**並べ替えの存在に気づけない。

### P2: 一貫性・磨き込み

- **P2-1. 言語の混在。**`Project Settings` / `Holidays` / `Add Holiday` / `Remove` / `Close` が英語。
  ツールバー・セルは日本語。
- **P2-2. ステータスセルが native `<select>`、進捗が素の number 入力。**ツールバー/バーとトーンが不揃い。
- **P2-3. 予定バー(親)が無地のグレー塊。**実績バーは進捗グラデがあるのに予定バーは進捗が読めない。
- **P2-4. 依存線が細いグレー + 小さい矢印。**ホバー/選択で強調されない。
- **P2-5. 週末と祝日の区別が無い。**どちらも同じ薄グレー。
- **P2-6. 空状態が統合/Gantt に無い。**タスク 0 のとき真っ白。
- **P2-7. ステータスバーが "Ready" のみ。**件数・選択数・ズーム・祝日数などのメタを出せる無駄領域。
- **P2-8. アプリ名/アイコン。**`index.html` の title が `wbs-gantt-outliner`、favicon が Vite ロゴ。

### P3: 細部

- タスク名のプレースホルダが `New Task`（英語）。
- セル編集中のフォーカスが背景色のみで弱い。
- ツールバーのアイコンのみボタン（Undo/Redo）以外に aria/title が少ない。
- `index.css` の `body { display:flex; place-items:center }` は Vite テンプレートの残骸。

## 4. 改善提案

### 4-1. デザインの土台（トークン化）

`tailwind.config.js` の `theme.extend` に最小のトークンを定義し、全体をそこに寄せる。

- カラー: `brand`（青系 50..700）/ `surface` / `border` / `text` / `muted`、
  予定=blue・実績=amber・完了=emerald・保留=amber の 4 系統に整理。
- 角丸: `sm=4 / DEFAULT=6 / md=8`。影: `xs / sm`。行高: 既定 32px（コンパクト設定で 28px も可）。
- タイポ: 12px（補助）/13px（本文・セル）/14px（見出し）の 3 段。

### 4-2. 画面構成（ヘッダー/サブバー/ステータスバー）

- **ヘッダー（高さ 44px）**: 左=ブランド + プロジェクト名、中央=ビュー切替（セグメント）、
  右=元に戻す/やり直す、`基準計画固定`（トグルピル）、保存/読込/エクスポート（アイコン+ラベル）。
- **サブバー**: ズーム（Day/Week/Month/Year をセグメント化）、`今日` ボタン、すべて展開/折りたたみ、
  表示項目（列）設定ボタン、件数表示。
- **ステータスバー**: 総タスク数 / 選択数 / 表示期間 / 祝日数 / ズーム。`Ready` を置き換える。
- **トースト**: 重ならないよう右上をずらす or 下端寄せ。エラー以外は自動消滅のまま。

### 4-3. ガント表現

- **今日ライン**: 縦のアクセント線（ヘッダーにもバッジ）。
- **週末/祝日**: 週末=薄グレー、祝日=薄アンバー+ヘッダーに印。月境界は現状の太線を維持。
- **バー**: 角丸を強め、予定=青ソリッド、実績=アンバー。親バーはロールアップ用に太めのキャップ + 進捗表示。
  バーが短いときはラベルを右外に出す。
- **選択**: 行全体（左ペイン + タイムライン）にハイライトの帯を敷く。グリッド背景より前面・バーより背面になる層で描く。
- **依存線**: 既定は細グレー、ホバー/選択で強調色 + 太さ。矢印を少し拡大。
- **ヘッダー**: 月ラベルはスクロール中も見えるよう sticky 化（またはセグメント内中央寄せ）。

### 4-4. セル/入力

- **P0-1 の修正**: `localStart` の初期値を store 値の表示形式で初期化し、同期条件を見直す（重なり解消）。
- ステータスをピル型セレクト（色付きバッジ）に、進捗は数値 + ミニバー表示に。
- 編集中は明確なフォーカスリング（控えめな blue リング）を付ける。

### 4-5. 一貫性

- ダイアログを日本語化し、`rounded-xl / shadow-2xl` のトーンをヘッダー等にも適用（dialog の見た目は既に良好）。
- 列設定は右クリックに加えてサブバーのボタンからも開けるようにする（発見性）。
- 空状態を 3 ビュー共通で用意。

## 6. テストへの影響（重要）

既存テストが依存している DOM フックは維持するか、変更時に追随させる。

- 維持推奨: `input[data-field="..."]`（title/planStartDate/planEndDate/startDate/endDate/planDuration）、
  `button` の名前（`WBS` / `統合表示` / `ガントチャート` / `すべて展開` / `すべて折りたたむ`）、
  `label:has-text("基準計画固定") input[type=checkbox]`、`button[title*="元に戻す"]` / `やり直す`。
- 変更が必要: Garnnt 予定バーの `bg-blue-100` クラス（`e2e/dependency-auto-calculation.spec.ts`）、
  依存ハンドルの `title="Drag to create dependency"`。配色を変える場合は e2e セレクタを更新する。
